# Every container of schema names in src/ and scripts/, classified. Enumerated by
# scripts/schema_container_census.py; `--check` aborts the drill on any container missing from here.
#
# WHY THIS FILE EXISTS. NINE separate structures keyed by schema went unregistered, one at a time,
# and each time the drill charged the resulting failures to the codebase instead of to itself:
# SUPPORTED, GROUPED_LAYOUT, FEATURE_PACK, V2_1_LINEAGE, the two census maps,
# `_EXPORTABLE_TABLE_SCHEMAS`, the exporter CLI's argparse `choices`, `OBSERVATION_SCHEMA_CLI_CHOICES`,
# the exporter's own inline validation set, and `_EXPORTER_SCHEMA_CHOICES` in the lattice. Each was
# found by running the full drill (17-70 minutes), reading a stack trace, and adding the one it named.
# That loop does not converge: after each fix the instrument still had no way to say what it had
# MISSED, so a clean run only ever proved the structures I had thought of were registered.
#
# THE CENSUS'S OWN DENOMINATOR WAS WRONG TWICE, which is the same defect one level up:
#   - it scanned Set/List/Tuple and not Dict, so `OBSERVATION_SCHEMA_CLI_CHOICES` was invisible;
#   - it scanned string LITERALS only, and its docstring asserted that containers of version
#     CONSTANTS were "covered by the property-tuple mirroring plus PRECONDITION 2". False for an
#     ad-hoc set inline in a function body -- which is exactly what the exporter and the lattice have.
# Extending it from 3 node types and 1 member shape to 4 and 2 took the count from 8 to 19.
#
# Format:  REGISTER|PARTIAL|MIRRORED  <file>  <comma-separated members>
# Keyed on file + members, NOT on line number, which drifts.
#
