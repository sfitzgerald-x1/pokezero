# The default rubric (`schema_drill_expected_breakages.txt`) means "this test's subject IS which
# schema is currently default". Under a WIDTH change that population is different: every site that
# legitimately NAMES a width -- a census assertion, a fixture pinning a v4 shape, an encoder
# refusing an off-census spec -- is a legitimate break too, because the synthetic schema really is
# one column narrower.
#
# Sharing one file would have two failure modes and both are bad: fail the run on correct
# behaviour, or let a real SHAPE conflation hide behind an entry admitted for the naming run. That
# second one is the whole reason the naming rubric carries an admission rule.
#
# WAS UNPOPULATED ON PURPOSE, and the note said the intended first use is: "run it, read every
# breakage, and admit only the ones demonstrated to be legitimate width-naming, one at a time, with
# the demonstration recorded." That is what happened, and it happened only after the causes that made
# earlier attempts untrustworthy were closed: the both-buckets symptom (an inert `_norm_id`, `\$`
# matching a literal dollar), the census-floor defect (the floor now narrows WITH the width, both
# derived from the outgoing default), and the arm cloning v4 while the outgoing default was v2.2.
