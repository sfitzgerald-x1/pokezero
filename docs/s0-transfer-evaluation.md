# Scoring a fused S0 milestone

Prepare once on CPU with `python -m pokezero.s0_transfer_harness prepare --spec SPEC --out DIR` and the existing runtime, Foul Play and staged bridge arguments. Each entry in `SPEC.replicas` contains its integer `replicate`, absolute fused `run`, original `reference_run` (owns game-zero B) and a `dispatch` object with the absolute path and SHA256 of the trainer's committed milestone request. Supply the common `route_declaration_sha256`, cadence, two banks, seeds, input convention and champion binding. Use the live evaluator-visible trainer mounts for both paths, including when both trainers call their own volume `/out`. Preparation checks the trained snapshot against the dispatch and committed fused state. The reference run must match the initial snapshot recorded in that state.

Run the engine side once. Split the Showdown side across CPU workers by passing `--shard I/N` to each `s0_transfer_supervise showdown DIR` invocation, with I from zero through N−1. Choose N and `--deadline-seconds` using the measured games/hour and the deadline for this look. Give each worker the same runtime and bridge arguments. Start the workers together. Each shard owns one append-only terminal ledger. After an interruption, use `--resume` with the same directory and shard to continue unattempted cells. Completed failures, refusals and caps retain their original dispositions. A coordinated restart uses a common increasing `--attempt N` on its workers (the first run defaults to 0, the first resume to 1). Set it explicitly if shards have different retry histories. Shard zero joins receipts for that attempt or a later one. For a selective retry, resume individual workers and run the standalone scorer when they finish.

Showdown shard zero waits for the engine and the other shards until its worker deadline. It scores durable rows even after a timeout or nonzero worker exit. An exclusive lock prevents scoring while a worker writes. Allow an additional `--score-seconds` (default 300) on the coordinator for quiescence and scoring. Its terminal receipt distinguishes worker and scorer exit codes. To score sealed ledgers separately, run `python -m pokezero.s0_transfer_recompute DIR`. This writes `scores.json` and, for registered looks, `route-verdict.json`. Missing cells stay in the denominator. For the trusted stop owner add `--publish-stop` to the scorer or the shard-zero supervisor and supply the signer's existing key through `PZ_S0_ROUTE_STOP_KEY`. Before delivery the scorer pins its original FAIL and scores by digest under `stop-evidence/`. Repeating `--publish-stop` completes that same decision even if other rows arrived. The signer checks both trainer bindings before delivery. Only a robust valid FAIL publishes a signed stop to each replica for the next committed boundary. The trainer records the enabled flag, route binding and public key fingerprint in `route-stop-authority.json`. A route-bound trainer refuses startup without its key. Generic deferred runs record disabled authority.
