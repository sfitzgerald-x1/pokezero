Why the history tail is not touched. The pack exists to serve an arm that runs at transition_token_budget = 0. Resizing the history region would confound the exact comparison the pack is built to make, so v4 inherits v3's 64-row tail byte-for-byte.

The question v4 exists to answer

Five v3 arms differed only in history budget k. Pooled high-fidelity foul-play ordered them k1 > k0 > k8 > k64 — and history turned out to be the instability axis too: the k64 arm entered runaway dilution/sharpening cycles and collapsed while k0/k1/k8 traversed the same counts clean.

So: can a pure-Markov k0 policy match a k1 one, once the facts k1's single history row was carrying are named as current state? The existence proof is already in the tree — the consecutive-stall counter encodes the double-protect decision exactly, where raw history would spend a whole token row on it. v4 asks the same of nine more facts.

The organising principle is ONE PARSER TRUTH, TWO CONSUMERS: every parser-derived public fact should reach both the search world and the observation. The campaign's fix wave closed the world-side gaps. v4 is that audit run in the opposite direction — facts the searched world is seeded with (or that only the history region carries) which the observation never saw.

v4 is v3's grouped layout with the pack appended inside its semantic group, not bolted onto the end. Three of the seven groups grow; the other four are untouched.

Part A rides each side's ACTIVE mon token (within the two team blocks); Part B rides the single field token. Nothing is written to the action, stats, or history regions — which is exactly why the pack survives at transition_token_budget = 0.

Part A — per-mon current state

Every A-row is parser-derivable public information and Markov-legal: a function of the current public state plus the immediately-preceding round's public record — the same window the parser already holds.

A1 · Forced recharge

built NUMERIC_MUST_RECHARGE · v4 index 39 · active mon, both sides · 0/1

The correction that motivated the whole pack. An earlier status relay claimed k0 already saw this. It did not, on the side that matters. mustrecharge is not in TRACKED_VOLATILES, so no categorical could ever be emitted and no numeric column existed. The self side was covered by accident — a recharging mon's request offers exactly one action, so the action tokens collapse to a lone legal move:recharge. The opponent side was blind.

The one decision a k0 policy could not see

The -mustrecharge line lands on the turn the beam hits; the cant lands the turn after. So the flag is true across exactly one decision boundary — the one where the opponent is choosing what to do against a mon that cannot act. The protocol inventory calls -mustrecharge a "semantic alias" of the following turn's cant:recharge transition token, and that is precisely the problem: that row is history-region-only and one decision too late.

Why the parser line beats the search lane's reconstruction. engine_search already derived this fact from the round-indexed action record, and now prefers the parser tracker instead. The line is strictly stronger evidence: a missed Hyper Beam never emits it (so gen3's "a miss does not recharge" rule needs no special case), it names its own actor (no species-continuity anchor), and it cannot scroll out of a rolling window (no fail-open branch). One truth, two consumers.

A2 · Last executed move

built CATEGORY_LAST_USED_MOVE · categorical column 51 · active mon, both sides

The pack's largest single surface: what Encore locks, what a Choice-lock read corroborates, and the cadence anchor a k1 row was implicitly supplying. The parser already tracked last_used_move for the world — "Encore's own onStart READS it; a world that omits it makes Encore fail outright" — while the observation had no write anywhere.

Three states, all positive facts

Reusing the existing move:<id> family rather than a private lastmove:<id> one means the identity shares an embedding row with the same move on an action token — the token-type embedding supplies the context. That is why the pack costs zero per-move vocabulary rows: one sentinel plus the ability family, and nothing else.

A3 · Truant loaf phase

built NUMERIC_TRUANT_LOAF · v4 index 40 · active mon, both sides · 0/1

1 = this mon loafs on its next move attempt. The parser already runs the exact gen3 free-running toggle — switch-in seed this.turn !== 0, an unconditional flip at every residual, the post-upkeep replacement guard, and the traced-Truant unknown state — because the world needs it. The observation never saw it.

Why the bit and not the obvious proxy. The toggle flips at every residual whether the mon moved, slept, flinched, was paralysed, recharged, or did nothing. So "moved last round → loafs now" is a proxy that de-synchronises the first time a holder fails to move for a non-Truant reason — and stays inverted for the rest of the stint. 0 encodes both "no holder" and "phase unknown", mirroring the world's None fallback, which never asserts a phase it cannot prove.

A4 · Current traced ability

built CATEGORY_TRACED_ABILITY · categorical column 52 · active mon

The ability the mon is currently borrowing via Trace, cleared on switch-out.

Why the belief channel is the wrong source

A5 · Last-round damage

built NUMERIC_LAST_DAMAGE_DEALT / _TAKEN · v4 indices 41–42 · active mon

Point evidence from the previous round, as a fraction of max HP. DEALT is move-attributed only — untagged -damage on the slot opposite the open move window's actor. TAKEN is total: every -damage on the mon, tagged or not, so it includes residuals, hazard chip, recoil and confusion self-hits.

The ledger settles at each turn boundary, and is keyed to the MON

dealt (move-attributed) taken (all sources)

The pair is deliberately not a mirror: DEALT is move-attributed while TAKEN is total, and both are keyed to the mon, so a mon that just switched in reads 0/0 even though its side dealt and took damage last round. The one attribution error this surface could make is the confusion self-hit — a slower confused mon self-hits with an untagged -damage and no move line of its own, so the |-activate|SLOT|confusion marker closes the move window and keeps that damage out of the previous mover's DEALT column.

Point observation only. The range/stat/variant inference this evidence feeds is the belief layer's job (the Tier-2 residual lane) and is explicitly out of scope: these columns state what happened, they do not conclude anything from it.

Part B — hazard payoff and credit

The credit-assignment fix. Spikes pay off turns after they are laid, in nobody's visible state, so the value head regresses on states that never contain the layers' realized payoff.

Orientation, shared with NUMERIC_SELF_HAZARDS / NUMERIC_OPP_HAZARDS: SELF_* is about our own ground — layers on our side, damage our mons suffered, items of ours knocked off. OPP_* is the opponent's ground, i.e. where our Spikes' and our Knock Offs' payoff shows up. So "credit we earned" is always the OPP_* column, exactly as "layers we laid" is NUMERIC_OPP_HAZARDS.

B1 + B2 · Hazard credit accrued, and expected remaining value

built v4 indices 114–117 · field token · per side

A matched (spent, remaining) pair on one scale

B1 · realized (already taken off) B2 · expected remaining

Worked example — one Spikes layer on our side; Snorlax already ate 12%; Slaking (grounded) and Skarmory (Flying, exempt) on the bench.

B1 · realized 0.12 ÷ 6 mons 0.020
B2 · remaining 1 grounded bench mon × 1⁄8 ÷ 6 mons 0.021

Where ~0.02 sits on the team-HP scale both columns share:

One layer is worth a couple of percent of a team either way — and B1 and B2 land in the same place because roughly as much is still owed as has already been paid. Both use the same six-mon denominator, so they read as one (spent, remaining) pair rather than two unrelated scalars. Skarmory is excluded by the engine's own grounding rule (Flying types and Levitate are exempt); Snorlax is active, so it already paid.

Grounding is evaluated from public knowledge only and is conservative by construction: an unrevealed bench mon, or one whose ability is still ambiguous, counts as grounded. For an expected-value column the honest failure direction is to over-count, never to claim an immunity we cannot see. Our own team is fully known, so the same code is exact on the self side.

B3 · Opponent switch propensity

already present — not re-added NUMERIC_STAT_OPP_SWITCH_COUNT + the per-mon triple

The global (switch count, decision opportunities) pair plus the per-mon (switched-before-attack, stayed-and-attacked, turns-active) triple are already encoded, evidence-mass /64, never bare rates — and the triple is already keyed to the mon that switched out. v4's contribution here was verifying that and changing nothing. See the proposal at the end of this page for the part that is missing.

B4 · Items-removed credit

built v4 indices 118–119 · field token · per side

Per-side count of held items publicly removed by the other side's action (-enditem … [from] move: Knock Off). Per-mon removal state was already encoded; what was missing is the credit aggregate the value head needs to price a Knock Off whose payoff is spread over the rest of the game. Trick is excluded — it is a swap whose giving half the belief layer explicitly declines to model, so counting it as removal credit would price a trade as a theft.

Normalisation: why /6 and not the /64 evidence-mass convention

A team can lose at most six items, so /64 would pin this column under 0.1 for its entire life and its realistic range (0–2 items) into the bottom 3%. That matters mechanically: the numeric vector goes through one linear projection, and the gradient on a column's weights is proportional to its input value — a 10.7× smaller input learns proportionally slower against a shared learning rate and grad-norm clip. /6 also matches the team-HP denominator B1 and B2 use, so the whole Part-B block reads on one scale. This is a documented, deliberate deviation from the plan's sketch.

Adjudication caveat (binding, inherited from the plan). FoulPlay's knock-off rate is not automatically the target. Before any training reads this column as a deficiency signal, a G4-style counterfactual probe — replay lost games, search the loser's seat, certify across reseeds — must adjudicate whether self-play's lower usage is actually a deficiency.

Matchup-conditional switch tendency

Two columns on each opponent mon token

built NUMERIC_MON_SWITCHED_VS_ACTIVE / _STAYED_VS_ACTIVE · v4 indices 96–97 · all six opponent tokens

B3's per-mon triple is keyed to the right mon but still marginalises over the thing that determines the behaviour: what it was facing. Switching in gen3 is almost entirely matchup-driven — Skarmory stays in on Snorlax and bails from Magneton. A per-mon rate of "bailed 3 of 7" averages over whatever matchups the game happened to present.

What the marginal count throws away

The conditioning variable is free — we know our own active at encode time — and the pair is the literal conditional form of the marginal triple's first two members. (bailed, stayed) rather than (bailed, opportunities) for two reasons: it is the stay-or-switch evidence exactly (a cant turn is an opportunity but not a stay-or-switch datum), and both halves are accumulated at live hook points in both the batch and the incremental fold, so the parity twins cannot drift — an opportunity count would have had to be rebuilt from a turn map the incremental fold prunes. Normalized /8, and it rides the same tendency mask as the triple: same channel, conditioned. Writing it on all six tokens answers two questions at once: will the mon in front of me bail, and which of their mons has historically been willing to face what I have out.

Why this belongs to this campaign. The aggregate survives at k0 (it is a token column, not a history row), but the matchup context of each switch is carried solely by the transition rows — so at k0 the model sees "Skarmory bailed 3 times" with no way to recover what it bailed from. And the sharper argument: the raw form of this information was fully available at k64, the worst and least stable arm. The model could not use it; it diluted. That is the pack's central thesis in miniature — if the sufficient statistic is the useful form, encode the statistic rather than widening the window.

The honest limits.

  • Sparsity. A game visits maybe 10–25 of the 36 pairings at a few turns each, so a cell is usually small and is empty early. Mitigated rather than solved by the pair encoding — (1, 0) and (1, 4) stay distinguishable, which is exactly why the design doc forbids bare rates — and an empty cell degrades cleanly to the marginal triple sitting on the same token.
  • It was not in the plan. The Part A table does not contain it and the §5 probe's bucket list does not either — it is an owner-approved addition on top. A matchup-conditional switch read is a plausible member of the probe's residual bucket, which the plan calls "the falsifier."

Contract consequences

Every v4 column extends both censuses, so a v4 checkpoint can never share a cache, an env, or a lineage with a v3 one. The machinery refuses to mix them at every layer, by design: schema validation, the encode-time census floors, the checkpoint-provenance latch, and the search-lane contract pin. v2.2 remains the fresh default — adding a schema never moves it, so every running arm keeps collecting under the schema its checkpoints were trained on.

The vocabulary is the same kind of latch. The pack's two categorical families are opt-in via gen3_category_vocabulary(include_feature_pack_v4=True), exactly like include_turn_merged, because extra rows change the vocabulary size and therefore every embedding table's shape. With the latch off, the enumeration is byte-for-byte what every v2.2/v3 checkpoint was trained against — which is what makes v4 safe to land while those arms are still running.

ObservationFeatureMasks.feature_pack_last_move makes A2 independently ablatable, so the plan's arm pair — k0+pack vs k0+pack+lastmove — is two arms differing in exactly one column.

Known gaps

  • Rust leaf encoder / MCTS-eval lane. mcts_eval/resolver.py still lists only v2.2 and v3, so a v4 checkpoint entering that lane is refused loudly rather than silently mis-encoded — the correct fail-closed behaviour until rust/pokezero-search/src/encoder.rs can express the pack. The Python exporter already emits v4 tables. The training and high-fidelity foul-play lanes do not touch that encoder.
  • Golden-corpus regeneration at v4 — the same gate v3 carries.
  • The §5 attribution probe has not been run. It is offline and costs no fleet time. The plan sequences it before the arms so the pack can be trimmed to the rows whose buckets actually show up.
